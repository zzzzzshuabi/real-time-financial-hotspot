# 01 · 系统架构设计

## 1. 设计目标

| 指标 | 目标 |
|---|---|
| 行情延迟 | tick 推送到计算结果 < 1s |
| 快讯延迟 | 发布到入库 < 30s |
| 热点刷新 | 每 10s 重算一次 Top 榜 |
| 可用性 | 单数据源故障不影响整体，系统年可用性 > 99.5% |
| 扩展性 | 新增数据源 / 新市场只需加一个 collector 进程 |

## 2. 六层架构

### 2.1 数据源层
只负责"拿到原始数据"，不做任何业务计算。
- 行情 WS、HTTP 轮询、RSS、爬虫、第三方 SDK
- 每个源一个独立 collector 进程，崩溃隔离

### 2.2 接入层（Ingestion）
- 协议适配：把不同源的报文统一成内部标准事件 schema
- 清洗：编码、时区、字段对齐、垃圾数据过滤
- 去重：SimHash（文本类）、主键三元组（行情类）
- 限流：对每个外部源做 QPS 限速，礼貌抓取
- 输出：统一投递到消息队列

### 2.3 消息层（Message Bus）
- Kafka（生产）或 Redis Stream（MVP）
- 主题划分：
  - `tick.{market}` —— 实时行情
    - `news.raw` —— 原始快讯/新闻
      - `announcement.raw` —— 公告
        - `social.raw` —— 社媒讨论
          - `hotspot.result` —— 计算后的热点结果
          - 作用：解耦采集与计算、削峰填谷、支持重放

          ### 2.4 实时计算层
          四个并行引擎：
          1. **量价异动引擎**：监听 tick 流，检测涨跌幅/量比/突破
          2. **资金流引擎**：聚合分钟级主力净流入、北向数据
          3. **舆情热度引擎**：新闻/社媒文本 NLP，计算讨论增速与情感极性
          4. **事件催化引擎**：关键词匹配（政策、合同、业绩预告）

          每个引擎独立消费消息队列，输出写回 `hotspot.result`。

          ### 2.5 存储层
          详见 [05-storage.md](05-storage.md)。
          热数据走 Redis，温数据走时序库，冷数据走对象存储。

          ### 2.6 服务与推送层
          - REST API：供前端查询历史热点、榜单
          - WebSocket：向前端实时推送新热点
          - Bot 推送：企微 / 钉钉 / Telegram / 邮件
          - Webhook：推给自定义下游

          ## 3. 关键设计原则

          - **无状态计算**：计算层不存状态，状态全在 Redis/DB，方便水平扩缩
          - **背压控制**：下游消费慢时，消息队列缓冲，不直接压垮采集器
          - **可观测性优先**：每个 collector 上报延迟、成功/失败数、错误率到 Prometheus
          - **配置即代码**：股票池、板块映射、告警阈值全部在配置文件/DB，热更新
          - **失败重放**：原始报文全部落 MinIO，算法升级后可离线重算

          ## 4. 进程拓扑（MVP 参考）

          ```
          collector-tick  ──┐
          collector-news  ──┤
          collector-social ─┼──► Redis Stream ──► worker-hotspot ──► Redis ZSet (实时榜)
          collector-flow  ──┘                      │
                                                   ├──► PostgreSQL (热点日表)
                                                                                            ├──► Elasticsearch (新闻索引)
                                                                                                                                     └──► notifier (企微/钉钉)
                                                                                                                                     ```
